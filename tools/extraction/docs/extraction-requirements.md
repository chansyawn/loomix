# 提取要求与规范

本文说明修改提取规则和验收逻辑时不能放宽的约束。具体业务的准入依据、适用版本及未决问题见[业务确认与调查](business-investigation.md)。

## 解释与证据原则

- **区分三种状态。** 未知不是默认值，已确认缺失不是解析或导出失败；不能把失败记成缺失后继续发布。
- **只认明确关联。** 不用同名、同编号或恰好能读出值来推断关系。对重复显示配置比较所需字段的语义值，而非引用地址；有冲突就停止，不能由读取顺序决定结果。客户端用语跟随当前游戏显示，不沿用旧称。
- **按需建模。** 游戏只用文案说明的特例，默认保留原文和已知的适用范围。只有能从配置、文案或已验证的游戏行为中确认规则，且查询、计算或校验确实需要区分其中的条件时，才将这些条件拆成字段或枚举。
- **保留决策依据。** 读取记录保留候选、排除项和未确认原因，字段依据指向最终值的来源。新增判断应记录可定位的证据及适用版本，无证据则标为待确认。

## 收录准入

正式收录需有独立、可定位的证据，不能从客户端图鉴记录、网站可见性、已有图标或配方等关联倒推。证据只支持关联时，不扩大正式收录范围。人工补充须绑定版本、核对客户端身份并记录确认来源，不补造属性或关系。各类收录的定义见[领域术语表](../../../GLOSSARY.md#收录与图鉴)。

## 外部资料

外部资料只补充客户端无法提供的事实，不覆盖客户端证据。每条记录应能回溯来源；目标游戏版本、数据修订及实体引用必须与客户端快照匹配。版本不符、引用无效或记录冲突时中止，不能静默丢弃。外部资料随提取结果封存，后续编辑不改变已有结果。

## 流水线的设计要求

- **同一快照，冻结输入。** 不混用客户端快照、配置、资源清单或外部资料。保留冻结来源、选图候选和映射；相同像素不证明源对象相同。影响提取的输入、实现或工具变化后，应产生新的结果身份。
- **缓存只做加速。** 缓存复用前须复验，已封存结果必须能脱离缓存验收。打包只接受已经验证的提取结果。
- **可重现性不等于正确性。** 同一份读取记录应能组装出相同字节；仍需独立对照冻结来源，核对读取、分类、关联和选图。修改来源解释时，要能拒绝数据和字段依据一起被改错的结果；整链验收还要核对实际客户端文件。
