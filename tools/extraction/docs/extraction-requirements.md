# 提取要求与规范

本文面向提取工具维护者，说明跨业务的解释原则、收录准入、客户端用语、外部资料与流水线的设计要求。客户端换版与调查见[提取维护](extraction-maintenance.md)（待补充），操作步骤见[客户端资源提取](../README.md)，概念见[领域术语表](../../../GLOSSARY.md)，共享数据语义见[共享数据契约](../../../packages/schema/README.md)。字段映射、算法、版本参数与产物结构以对应实现为准。

## 解释与证据原则

- **三种缺失分别表达。** 未知、已确认缺失与解析失败必须区分：缺少证据不能变成默认值，配置存在但无法解析或导出的情况也不能记为缺失。
- **优先明确关联。** 关系和类型只采用客户端明确关联及当前显示配置，不按名称相似或“碰巧可读”推断。显示配置可能有重复 ID，应比较所需字段的语义值；相对引用地址不同不代表值不同，范围内语义冲突必须停止，避免读取顺序决定结果。
- **记录可追溯。** 客户端读取记录保留排除项、候选值和未确认原因；字段依据报告说明最终字段来源。新增判断时记录来源和适用版本，缺少原始依据时标为待确认。

## 收录准入

客户端图鉴条目存在、是否计入客户端图鉴列表与是否属于本站正式收录是三个不同判断；页面可见或关联视图可浏览也不等于正式收录。

- **正式条目。** 必须有可定位证据和适用版本。名称、图标、配方引用或相同编号本身不能证明正式收录资格。
- **人工补充。** 必须版本绑定、通过客户端身份校验，并记录确认来源；不得补造描述、属性或关联。
- **仅供引用。** 可因配方、掉落、玩家服饰对应或送礼偏好等关系保留身份，但不获得独立详情。
- **范围外引用。** 不扩大正式收录范围，其表示方式遵循[共享数据契约](../../../packages/schema/README.md)。
- **具体业务。** 各领域的准入名单与已确认结论见[业务确认与调查](business-investigation.md)；本节只定义通用边界。

证据冲突或无法确认时，按“解释与证据原则”处理；不能用读取顺序或默认值掩盖。

## 客户端用语

- **一致性。** 提取结果和网站展示使用的客户端用语必须与游戏内显示保持一致；游戏内用语变化时同步调整，不另造名称或保留旧称。
- **来源。** 具体名称以当前版本的客户端 TextMap 为准，本文不列对照表。

## 外部资料

外部资料只补充客户端无法提供的事实，不覆盖或改写客户端证据；人工补充收录见“收录准入”。来源、业务解释与未确认事项见[业务确认与调查](business-investigation.md)。

- **版本绑定。** 必须声明目标游戏版本与数据修订，并与本次客户端快照一致；不匹配即中止。
- **身份与引用。** 只能使用目标客户端版本的物品或集合身份，并按领域规则校验类型、系列、成员关系和引用；重复、冲突或无效条目直接中止，不能静默丢弃。
- **可追溯。** 每条记录可定位到文件、指针和字节哈希；来源、适用版本与确认状态一并记录。

外部资料的封存与变更规则见“流水线的设计要求”。具体结构与校验参数以[共享数据契约](../../../packages/schema/README.md)和对应实现为准。

## 输入一致性

一次提取只使用同一客户端快照及其匹配的配置、资源清单和外部资料；不得混合不同客户端快照、配置来源或外部资料版本。提取身份绑定这些输入以及实现与工具的内容哈希，任一项变化都产生新的结果身份。

## 流水线的设计要求

流水线按读取 → 组装 → 打包推进：读取记录保存值、依据与图片用途，组装产出游戏资料集，打包只接受已验证的提取结果。以下约束跨阶段成立，以额外存储和复验成本换取可复核、可重现，后续重构不得削弱：

- **封存输入与选图候选。** 冻结来源、选图候选和图片映射，使选图能在不依赖易变输入的情况下复核；源对象身份与图片内容身份分开记录，避免相同像素掩盖不同来源。
- **外部资料封存，缓存只做加速。** 外部资料随提取结果封存，既有结果不随源文件修改而改变；缓存不能作为结果或验收依据，复用前必须重新验证，完整结果应能脱离缓存验收。
- **可重现性与正确性分开验收。** 同一份读取记录必须重新组装出相同字节；独立来源验收对照冻结输入，检查读取、分类、关联和选图是否正确；涉及来源解释的变更，还要验证“数据和字段依据一起被改错”会被拒绝；整链验收核对实际客户端文件。
