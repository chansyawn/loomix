# 业务确认与调查

本文只记录影响收录或解释的业务证据及待验证问题。除另有注明，证据来自客户端 `0.95.2`、数据修订 `1449213`，换版须复核。客户端配置、客户端试算和游戏实际行为是不同的证据；未实测不作运行时结论。复核入口见[客户端资源提取](../README.md#输入缓存与产物)。

## 物品与集合

- 客户端内容表是非外观条目的收录依据之一；表外物品须有领域依据或列入[补充收录清单](../src/extraction/source/catalog/supplemental-admissions.json)，人工确认依据见各条记录。
- **待确认：** 生物、植物和菜肴主题集合引用了家具图标。先核对游戏实际展示用途，不能凭资源存在断定它就是主题图，也暂不以成员图替代。

## 物品价格与交易

### 购买报价与上架条件

- 格连、络米电视购、友邻衣橱和星空街市须从非测试店页追到商品组，并确认直接交付物、支付货币和金额。解锁卡报价归卡片；万礼馆独立使用表 `672`，首字段 `9` 重复，需结合交付物 ID 区分，不能套用通用商品表 `659` 的次数价关联。有价不等于有入口，例如衣橱组 `503` 的冬日雪宴裙、发饰和鞋；有入口也不证明已开放。
- **眠月睡袍：** 电视购的商品 `302`、`515` 都交付玩家款，分别为 1,500、1,800 足迹，不是 600 友邻服饰币的同名衣橱款。两条都在「每日上新」，但低价行的追踪器 `3509`、`3510` 与篝火任务相关，任务 `4322` 文案明确要求买袍换装（文本键 `2452989747`）。需用同一账号对照任务推进前后两条商品的可见性、可购买性和确认价；实际页面来自返回的 `PageList` / `GoodList`（`TVShopData.lua:60`、`:838`，对象 `b3a5aba1`）。
- **格连异价：** 简约饮水器在每日刷新页 `25–27` 为 290 碎钱、限时页 `71` 为 360 碎钱（表 `659`、`665`）。粉白陶瓷杯在限时页 `70` 和任务固定页同为 150 碎钱；固定页 `49–51` 的任务关联可由追踪器（对象 `4f3420ed`）和任务文案（文本键 `2825703257`、`216535044`、`715774891`）交叉核对。只提购买用途的文案不能限定金额，相同金额也不能合并适用条件。弹窗另按单价乘折扣后向上取整（`GlennShopPanel.lua:245`，对象 `ec91e089`）；游戏内两种报价能否同时购买仍待实测。
- **次数价与试算：** 表 `663` 按商品 ID 配置每日次数价。星锚商品 `2` 的配置基价为 300 足迹，次数 `0/1/2` 是 `100/200/200`；礼帽魔术券次数 `0` 明配零价，并非缺值，使用街乐果冻（文本键 `974612840`）。电视购弹窗用运行时单价、已售数匹配次数档；匹配后，多件试算对未列次数沿用最高次数档，不匹配则按运行时单价乘件数（`TVShopData.lua:648`、`:731`，对象 `b3a5aba1`）。这不是服务端成交或限购证据。
- **货币身份：** 表 `318` 有四种「碎钱」，格连用 `200002`（文本键 `2798898123`）；衣橱服饰币不足时可用等额碎钱补足（文本键 `88034602`），不是第二条商品报价。图标同样按 ID 加载（`CommonCoinItemView.lua:182`，对象 `a263af52`）。背包枚举（`BackBagCommon.lua:12`，对象 `88ca166d`）、物品标签和实际支付用途不是同一名单：星果 `200019` 在枚举外，只按「货币」标签则会漏掉足迹和友邻服饰币。

### 回收、菜市与充值

- **菜市调价待实测：** 表 `152` 与教程表 `711` 都指向每日 `12:00`、`20:00`；帮助文本键 `353026141` 却称 `04:00` 调价、中午和晚间只更新种植量。观察游戏内菜价板实际变化时间。寄售由卖家定价（文本键 `1380489113`），梗力收购随收购品和舞台表现调整（文本键 `974728160`），不能套用菜市或普通出售规则。
- **菜市原价与普通回收价不能混用。** `GeLianFoodMarketPriceItem.lua:107` 将 `BItemCfg.price` 显示为原价、`FinalPrice` 显示为新价；`GeLianMarketSellAdapter.lua:42` 用前者折价并按市场范围限价（对象 `b3cf59e8`、`f56a4688`）。普通出售却按背包实例 GUID 调 `GetItemPrice`，预览汇总后取整数，提交 GUID、数量和 NPC ID（`BackBagData.lua:366`、`SellPacketPage.lua:177`/`:283`，快照 `Persistent/AssetBundle/blocks/00/00000002.blk` 内对象 `c567a48c`、`1cbbb641`）。衣橱回收另有 `GetNpcClothRecyclePrice`（`NpcClothGelianSellPage.lua:261`，对象 `df8c9b0c`）。
- **取价字段仍是候选。** `GameAssembly.dll` 中 `BItemCfg` 对应表 `325`（RVA `0x7b78f6a`、`0x7b7907a`），`BCropPriceRangeCfg` 对应表 `148`（RVA `0x7b6174a`）。按作物 ID 对照，表 `325` 字段 `14` 有值而 `13` 缺省，多数 `14` 等于菜市下限两倍、上限一半；梦幻果王小麦、水稻、辣椒为反例。访问器 RVA `0x78debc0` 读取字段 `14`，但尚未确认它的属性名，也没证明普通回收 `GetItemPrice` 读取该字段。原生入口可从绑定 `CSDefine.lua:914`（对象 `b72e7d7a`）追查，并核对传 GUID、传 GUID 加物品、只传物品数据三种调用（另见对象 `359d8fce`、`64a046e9`）。
- **验证路径：** 雅克想象帽的字段 `13/14` 为 `200/20`，粉眠恐龙睡衣为 `17500/3500`，后者格连购买报价为 `17000`。记录单件普通出售的预览与碎钱到账差额，再用同种不同星级生物检查实例差异。
- **地区充值价待实测：** 礼包和充值档位标识可从表 `153`、`157` 定位；「1 元 = 10 星果」只明确用于连接测试充值返还（文本键 `3918012022`），不能当作各地区实际售价。需核对带地区和币种的支付页。

## 外观与染发

- 发型、眼睛、眉毛和肤色按已确认的初始选项、电视购或卡池获取配置收录。电视购通过解锁卡关联发型和眼睛，部分对应外观不在客户端内容表；玩家截图用于核对发型正例。面部饰品只补录已确认礼包中的嘭嘭杏鲍菇雀斑，普通可穿戴面饰仍归穿搭。
- 灰色盘和专属默认色组没有解锁配置，因此不当作可选色组发布；默认色块仍可用于对应发型，白色盘仍可引用共享色块。
- **待确认：** 表 `46`、`47` 将混有直接商品和解锁卡的组 `82` 关联到星空街市「街市风尚／服装」，已解析的电视购页面中没有该组。需核实三测是否实际开放。

## 创想卡

- 卡片类型本身不足以准入：还需要与卡片同 ID 的制作配方，且产物须是正式家具。

## 生物

- 尺寸端点乘浮点系数，不用另一个恒为 100 的字段。该版本游戏内显示复核基线：薄荷炫彩灯鱼 1.5–2.5 厘、酢漿灰蝶 4.6–7.6 厘、红石蟹 5.2–9.2 厘、椰子螺 14–28 厘。
- **待确认：** 生物时间与栖息地候选表的关联。部分旧标签文本键已失效，应沿当前显示键与标签语义调查，不能仅凭同编号关联。

## 植物

- 种子需有可关联正式植物的确定性生长配置；追到栀子花丛、杜鹃花丛等正式植物后仍有配置阶段，不能截断。**成熟天数待确认**：阶段数和候选参数不能直接作天数，需游戏内观测或明确的运行时语义。

- 作物株须由已收录作物的成熟阶段与收获配置相互印证。花株按整张花株表中指向正式花朵的配置收录，幼苗、枯萎株、杂草及环境植物沿用原有身份。
- `ed.obb` 表 `144` 的成熟阶段与产物（字段 8、10）可与表 `137` 的收获物（字段 1）交叉核对。`137:10308` 缺少已收录作物的成熟阶段依据。
- 表 `241`（字段 1、2）中，灿黄百合株 `56000` 指向灿黄百合 `56200`，即使已收录种子的生长链未包含该花株，也能确认其收获物。该表中的 `50129` 未指向正式花朵。

### 花卉杂交

- 配方只维护在[人工维护 JSON](../data/external/flower-hybridization.json)。换版时核对攻略是否仍适用，并确认亲本和产物 ID 都属于目标客户端中的同一正式花卉系列。JSON 声明的目标版本不等于攻略已在该版本验证。
- 该版本已有矮牵牛杂交花色，但首批攻略未给亲本组合，不能从花色反推配方。成功率、攻略原适用版本及缺失亲本仍待确认。复核期间可使用绑定目标版本的空配方列表，本次提取将不包含杂交配方。

## 友邻与服饰

- 友邻以[友邻准入名单](../src/extraction/source/neighbors/allowlist.ts)为准。服饰须有明确的玩家服饰对应关系，或属于名单内友邻的专属服饰。
- 解包确认部分服饰的图标是通用云朵占位图，同一客户端仍能定位模型。它是缺图证据，不是服饰不存在的证据。[占位图回归样例](../src/extraction/source/neighbors/outfit-image.test.ts)

## 小栖地

- **发现条件：** 只收录能沿非 `(test)` 前置链回溯到装饰能力等级或任务直接解锁的模板。发现条件表和装饰能力等级表都支持 Lv.6；专注伏案地、裁荷清幽地和野风纳凉地据此准入，但尚未实测开放。截图只证明特定账号的发现状态，排序不证明准入；姹紫嫣红地仍无已确认的发现途径。
- **数量冲突：** 观星露营地（`1007`）的座椅在玩法表为 3、显示表为 2。两值分别保留，网站采用显示值，不能据此断定实际完成只需两把。[座椅差异回归样例](../src/extraction/source/vignettes/conditions.test.ts)
- **承载条件：** 户外餐厅地的食物只引用「置物桌」标签，没有桌尺寸、桌 ID 或要求行引用；晴日特调地饮品直接引用美食展台。食物是否必须放到计入尺寸要求的桌上、旋转是否影响匹配，仍需游戏内验证。
- **待确认：** 生态参数和预览资源保留在读取记录中，但生物出现时机、概率与预览逐件坐标不能从当前证据推出。

## 星海与星屿

- 星屿由区域探索列表或区域邂逅池明确关联后才能准入；未被引用或属测试的定义仅留在读取记录。详情展示物资可以引用目录物品，但不证明该物品正式收录或必然掉落；邂逅池也只提供候选，不证明友邻实际出场。
- **待确认：** 实际航路生成、掉落组如何分配及其概率、季遇状态对友邻出场的影响。地图预览虽可从资源索引找到，仍缺区域绑定证据；完整坐标与上游来源也待核对。
