# 业务确认与调查

本文集中维护具体业务的收录依据、已确认结论与待调查事项。跨业务解释原则与版本更新方法见[提取原理](extraction-method.md)，概念定义见[领域术语表](../../../GLOSSARY.md)。字段映射、算法及数量以代码为准；本文的既有调查结论不能自动推广到新客户端版本。

## 收录依据

客户端图鉴范围内的记录已由用户确认为开放内容；不计入客户端列表的外观也属于开放内容。额外实装物品的人工确认及指定分类由[版本绑定的补充收录清单](../src/extraction/source/catalog/supplemental-admissions.json)维护。

种子通过可连接正式植物的确定性种植关系准入，入口为[种植读取](../src/extraction/source/catalog/plants/read.ts)；友邻及其服饰通过对应准入规则筛选，入口为[友邻准入名单](../src/extraction/source/neighbors/allowlist.ts)与[友邻服饰](../src/extraction/source/neighbors/outfits.ts)。

## 花卉杂交

首批配方按用户提供的四张社区攻略图转录。客户端 `0.95.2`、数据修订 `1449213` 提供正式花朵身份、系列归属及获取来源标签。两株亲本到产物的关系来自攻略，成功率和攻略原适用版本未知。该客户端已有矮牵牛杂交花色，首批攻略未给出亲本组合。[人工维护 JSON](../data/external/flower-hybridization.json)

## 客户端显示用语

`0.95.2`（数据修订 `1449213`）活动配置 `ed.obb` 的中英 TextMap 将万象收藏称为 `Omnidex`（`2111100511`），杂物称为 `Miscellaneous`（`2110969575`），烹饪分类称为 `Dishes`（`3935948819`）。服饰套装使用 `Outfits`（`3935948846`），家具套组使用 `Sets`（`578165405`）。

同一份 TextMap 中，友邻服饰为 `Neighbor Outfit`（`301435305`），星屿为 `Islet`（`154047077`），创想卡为 `Inspo Card`（`180227326`），创想卡集为 `InspoBox`（`461758315`）。`Catalog` 是本站目录及路由用语，不是客户端「全部」（`All`）的显示名。

## 已确认与未确认的调查线索

- `0.95.2`（数据修订 `1449213`）的展示表 `325` 中，部分友邻服饰的大小图都指向 `UISprite/Load/Item/Cloud`。解包确认该资源为通用云朵图，同一客户端中仍可定位这些服饰的模型资源。资料集将占位云朵视为缺图，保留服饰及原始图片配置依据。[友邻服饰图标](../src/extraction/source/neighbors/outfit-image.ts)
- 生物尺寸换算曾通过游戏内显示交叉核对：薄荷炫彩灯鱼为 1.5–2.5 厘、酢漿灰蝶为 4.6–7.6 厘、红石蟹为 5.2–9.2 厘、椰子螺为 14–28 厘。核对支持使用端点乘浮点系数，排除另一恒为 100 的字段参与换算；字段读取见[生物属性](../src/extraction/source/catalog/records/creatures.ts)，数值样例见[内容测试](../src/extraction/source/catalog/content.test.ts)。这些是既有基线的核对记录，不能替代新版本验证。
- 成熟天数尚未确认。阶段数与候选参数不代表实际天数；应保留生长链和调查值，待游戏内观测或明确运行时语义确认后再发布。栀子花丛、杜鹃花丛等在已关联正式植物后仍有配置阶段，因此不能在首次命中正式植物时截断链。入口为[生长解析](../src/extraction/source/catalog/plants/growth.ts)。
- 生物、植物和菜肴主题集合引用了家具图标，其作为系列展示图的用途尚未确认，因此不以成员图片或拼图替代。后续需确认客户端实际展示用途，而不只是确认资源存在。
- 生物时间与栖息地候选表不能仅凭相同编号关联；部分旧标签文本键已经失效，应沿当前显示键与标签语义调查。入口为[目录词汇关联](../src/extraction/source/catalog/vocabulary.ts)。

客户端读取记录保留排除项、候选值及未确认原因。字段依据报告说明最终字段的来源。新增判断时记录来源和适用版本，无法找到原始依据时标为待确认。

## 小栖地

调查使用 `0.95.2 / 1449213` 的活动配置 `ed.obb`。玩法表 `288` 和显示表 `291` 按模板 ID 对齐。收录依据来自游戏内 Lv.5 时的观察、任务和对白，逐条判断记录在[准入清单](../src/extraction/source/vignettes/admissions.json)。游戏内观察保留的是调查结论。

排序 `32–34` 的三条模板共享发现线索 `6212`，触发条件及开放时点待确认。姹紫嫣红地排在 `99`，同样留作待证。名称带 `(test)` 的条目留在客户端读取记录中。客户端帮助文案 `443862490` 将备忘事项和装饰能力列为发现途径，玩家当下可见性取决于游戏进度。

客户端 `HabitatInfoPage.lua` 第 490–495 行从 `ReferEntities` 的 `RepairItem.Count` 构建显示条目，`HabitatInfoItem.lua` 第 87 行在数量前加 `x`。在 42 个可比模板中，只有观星露营地的座椅数量不同，玩法表 `288.10` 为 3，显示表 `291.7` 为 2，同一模板另列灿烂星双人椅 1 张。网站布景要求采用客户端展示数量。玩法计数如何纳入指定物品，以及实际完成判定，仍待验证。[表字段来源](../src/extraction/source/vignettes/profile.ts)

`HabitatInfoItem.lua` 第 177–195 行显示的是 `GridWidth` 和 `GridHeight` 分别除以 2 的结果。户外餐厅地、悠然野餐地的桌子和座椅展示 `1 × 1`，瓶花闲坐地的桌子展示 `2 × 2`。这五条要求的客户端示例家具均带有对应尺寸标签，包括映央小圆桌（1516）和映央大圆桌（1515）。网站据此使用相同宽高顺序的家具尺寸标签筛选候选。客户端实际的尺寸匹配算法及是否接受旋转仍待验证。[家具标签尺寸读取](../src/extraction/source/catalog/records/furniture.ts)

户外餐厅地（1006）的玩法表 `288.10` 分别记录桌子 `1,置物桌,2,2*2` 和食物 `2,置物桌,食物,2`，显示表 `291.7` 为这两条各自附上示例。食物条目的承载条件只引用「置物桌」标签，没有尺寸、桌子物品 ID 或要求行引用，玩法表 `288.11` 也没有为该布景配置物件关系。晴日特调地的饮品承载条件直接引用美食展台（1852）。网站在摆放规则中描述承载条件，图鉴仍可按承载条件反查。[布景要求读取](../src/extraction/source/vignettes/conditions.ts)

客户端 `HabitatTrackingItem.lua` 第 126 行调用 C# 接口 `CsHabitatModuleUtil.GetHabitatTotalProgress` 读取进度，`BlueprintHabitatData.lua` 第 54 行调用 `IsHabitatRestored` 读取完成状态。这些脚本只读取结果。食物是否必须放在计入尺寸要求的两张桌子上，仍需确认完成判定的实现或通过游戏内摆放验证。

生态参数及布景预览路径留在客户端读取记录中，生物出现时机、概率与逐件坐标仍待确认。

## 星海与星屿

调查使用 `0.95.2` 客户端的活动配置 `Persistent/Temp/5662883/GenerateAssets/ed.obb`，数据修订为 `1449213`。以下根表和字段编号来自该文件，文案取自同一文件的 TextMap。客户端使用「星海」「星屿」和「星海地图」等称呼。版本配置见 [profile](../src/profile.ts)。

星海资料收录区域探索列表与邂逅池里能确认归属的星屿。范围外的星屿定义与未确认的多区域候选保存在客户端读取记录中。详情页的展示物资可关联仅供引用物品，正式收录仍遵循物品目录的准入依据。

- **区域与星屿。** 根表 `652` 的区域为「禾夏H83区」「沐雪季·禾夏H84区」「塔法T31区」。每区的星屿向量（字段 `6`）与根表 `651` 按星系和层号分组的有序列表完全一致，可用星屿 ID 关联根表 `654`。这些列表只覆盖星屿定义的一部分，其余星屿的区域和实际航路生成规则仍待确认。H84 区的解锁提示指向禾夏 H83 区的对应星门。
- **物资。** 星屿详情的 `IslandDetailsPanel.lua` 读取 `displaybiologyicon` 和 `displayspecialtyicon` 展示「生物」及「特产」，分别对应根表 `654` 的字段 `25` 和 `26`，可用物品 ID 关联根表 `318`。空字段表示对应展示栏目缺少配置。根表 `655` 的资源映射还可关联根表 `563` 的掉落组，覆盖矿石、昼夜生物和季节植物。掉落组如何分配到具体星屿，以及数量和概率如何计算，仍待确认。
- **友邻。** `StarExploreTeleportationDetail.lua` 读取 `BStellarSeaNpcPoolCfg` 的 `layerlist` 和 `npcid`，填充区域的邂逅友邻列表。根表 `653` 的友邻 ID 对应根表 `41`，区域向量对应根表 `652`，同一行的星屿向量对应根表 `654` 中的 NPC 岛。多位友邻可以引用同一星屿。季遇文案说明当季友邻会随季遇结束远行，实际出场还需按游戏内状态核对。
- **图像与坐标。** 区域配置引用地图 SDF 和站点图，星屿配置可关联插画和雷达图标。地图预览图可从资源索引找到，预览图与区域的绑定仍待确认，因此保留为观察候选。`StarExploreTeleportationPage.lua` 从运行时列表读取星屿、星门与站点的 `Position.x/z` 并绘制图标。界面坐标换算已验证，完整坐标列表和上游来源待确认。
