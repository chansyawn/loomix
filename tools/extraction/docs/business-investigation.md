# 业务确认与调查

> **文档规则：** 各业务主题只记录 **准入规则**、**关键确认** 和 **待确认**。**准入规则** 说明收录范围；**关键确认** 只列非直觉、会影响提取判断的结论；**待确认** 记录未决问题和下一步。名称、图标、常规套组归属等直觉信息不逐项列举。
>
> **说明：本文不是最终结论。** 所有条目都是基于当前客户端版本和现有证据的工作结论，可能不完整或有误；新证据、游戏内验证或版本更新后应重新核对，不能把本文当作不可推翻的“真理”。引用前应回到客户端读取记录、字段依据和实际验证。

本文维护具体业务的收录依据、已确认结论与待调查事项。除特别注明外，结论基于客户端 `0.95.2`、数据修订 `1449213`，不能自动推广到新版本。跨业务解释原则见[提取要求与规范](extraction-requirements.md)，客户端换版与调查见[提取维护](extraction-maintenance.md)（待补充），概念见[领域术语表](../../../GLOSSARY.md)。字段映射、算法与数量以代码为准。

## 物品与集合

**准入规则**

- 客户端内容表中的条目（包括未计入客户端图鉴列表的外观）均由用户确认为开放内容，不要求出现在客户端列表。
- 表外实装物品必须列入[补充收录清单](../src/extraction/source/catalog/supplemental-admissions.json)，逐项记录 ID、预期名称、分类和人工确认说明；未列入且无其他领域准入依据的物品不纳入。

**关键确认**

- 暂无。

**待确认**

- 集合主题图：生物、植物和菜肴主题集合引用了家具图标，暂不以成员图片或拼图替代，需确认客户端实际展示用途，而不只是确认资源存在。

## 创想卡

**准入规则**

- 只纳入客户端物品类型为创想卡、存在与卡片同 ID 的制作配方，且制作产物属于正式家具的条目；缺配方或产物不在正式家具范围的卡片不纳入。

**关键确认**

- 卡片图片沿用客户端底图。

**待确认**

- 暂无。

## 生物

**准入规则**

- 沿用[物品与集合](#物品与集合)的通用收录规则，不另设清单。

**关键确认**

- 生物尺寸由表内端点乘以浮点系数得到，换算时排除另一个恒为 100 的字段；游戏内显示交叉核对为薄荷炫彩灯鱼 1.5–2.5 厘、酢漿灰蝶 4.6–7.6 厘、红石蟹 5.2–9.2 厘、椰子螺 14–28 厘。这些是基线，不能替代新版本验证。

**待确认**

- 生物时间与栖息地候选表不能仅凭相同编号关联；部分旧标签文本键已失效，应沿当前显示键与标签语义调查。

## 植物

**准入规则**

- 种子需有可关联正式植物的确定性生长配置（作物、固定幼苗或树木种植）；随机种植种子和不关联正式植物的种子不纳入。
- 花卉杂交配方只收[人工维护 JSON](../data/external/flower-hybridization.json)中列出的亲本组合；配方必须绑定目标客户端版本，并引用正式花朵系列中的正式花朵，未列出的组合不推断。

**关键确认**

- 该版本已有矮牵牛杂交花色，但首批攻略未给出亲本组合。

**待确认**

- 植物成熟天数：阶段数和候选参数不代表实际天数，需游戏内观测或明确运行时语义；栀子花丛、杜鹃花丛等在关联正式植物后仍有配置阶段，不能截断生长链。
- 花卉杂交成功率与攻略原适用版本未知；补充矮牵牛等已有花色的亲本组合。

## 友邻与服饰

**准入规则**

- 友邻只纳入[友邻准入名单](../src/extraction/source/neighbors/allowlist.ts)中的 ID；名单外友邻及其专属服饰不纳入。
- 友邻服饰需具备明确的玩家服饰对应关系，或归属名单内友邻的专属关系；两者都不满足的服饰不纳入。

**关键确认**

- 部分友邻服饰的图标指向通用云朵占位图；解包确认该资源是通用云朵图，同一客户端仍可定位模型资源。资料集按缺图处理。

**待确认**

- 暂无。

## 小栖地

**准入规则**

- 名称带 `(test)` 的小栖地一律排除。未收录的模板只保留在客户端读取记录中。
- 以同一版本的客户端配置为准。达到指定装饰能力等级或完成任务（包括友邻备忘）就能解锁的小栖地可以收录，算零步。如果要先完成其他小栖地，就逐个往回查。能查到一处直接解锁的小栖地，且沿途没有名称带 `(test)` 的小栖地，才收录。

**关键确认**

- 截图只用来核对账号是否已经发现小栖地，排序只用来决定展示顺序。
- 客户端 `0.95.2`、数据修订 `1449213` 的发现条件表和装饰能力等级表均支持 Lv.6。共享该条件的专注伏案地、裁荷清幽地和野风纳凉地符合配置准入。
- 网站采用客户端显示数量；已知只有观星露营地的座椅数量不同，玩法表为 3、显示表为 2。
- 家具尺寸显示值为原始宽高除以 2；尺寸标签用于筛选候选家具。
- 户外餐厅地的食物承载条件只引用「置物桌」标签，没有尺寸、桌子 ID 或要求行引用；晴日特调地饮品直接引用美食展台。

**待确认**

- 完成判定：玩法计数如何纳入指定物品，食物是否必须放在计入尺寸要求的两张桌子上。
- 尺寸匹配：实际匹配算法，以及是否接受旋转。
- 模板开放状态仍受游戏进度及服务器开放状态影响。三处 Lv.6 模板尚未实测，姹紫嫣红地尚未找到发现途径。
- 帮助文案可见性：帮助文案将备忘事项和装饰能力列为发现途径，玩家可见性取决于进度。
- 生态与预览：生态参数和预览资源保留在客户端读取记录；生物出现时机、概率与逐件坐标待确认。

## 星海与星屿

**准入规则**

- 星屿必须由区域探索列表或区域邂逅池明确关联，才能纳入正式资料；未被区域引用、归属不明或属于 test 的星屿只保留在客户端读取记录。
- 详情页展示物资可关联仅供引用物品，但不扩大物品的正式收录范围；物品本身仍按物品目录准入。

**关键确认**

- 区域探索列表与邂逅关系一致，可用星屿 ID 关联星屿定义；H84 解锁提示指向 H83 区星门。
- 星屿详情展示生物和特产，物资关联物品目录；资源映射可关联掉落组，覆盖矿石、昼夜生物和季节植物。
- 区域邂逅列表关联友邻；多位友邻可引用同一星屿。
- 区域与星屿配置可关联地图、站点图、插画和雷达图标；界面坐标换算已验证。

**待确认**

- 星屿覆盖与航路：列表只覆盖部分星屿定义，其余区域和实际航路生成规则待确认。
- 掉落分配：掉落组如何分配到具体星屿，数量和概率如何计算。
- 友邻出场：季遇友邻会随季遇结束远行，实际出场需按游戏内状态核对。
- 地图预览：预览图可从资源索引找到，但与区域的绑定待确认。
- 坐标来源：完整坐标列表和上游来源待确认。
