# 业务确认与调查

本文维护具体业务的收录依据、已确认结论与待调查事项。除特别注明外，结论基于客户端 `0.95.2`、数据修订 `1449213`，不能自动推广到新版本。跨业务解释原则见[提取要求与规范](extraction-requirements.md)，客户端换版与调查见[提取维护](extraction-maintenance.md)（待补充），概念见[领域术语表](../../../GLOSSARY.md)。字段映射、算法与数量以代码为准。

## 收录依据

客户端图鉴范围内的记录已由用户确认为开放内容；不计入客户端列表的外观也属于开放内容。额外实装物品的人工确认及指定分类由[版本绑定的补充收录清单](../src/extraction/source/catalog/supplemental-admissions.json)维护。

种子通过可连接正式植物的确定性种植关系准入，入口为[种植读取](../src/extraction/source/catalog/plants/read.ts)。友邻及其服饰通过对应准入规则筛选，入口为[友邻准入名单](../src/extraction/source/neighbors/allowlist.ts)与[友邻服饰](../src/extraction/source/neighbors/outfits.ts)。

## 创想卡

创想卡首批以正式家具为产物范围，要求客户端物品类型与同 ID 制作配方共同确认身份。正面沿用客户端底图，由网站叠放产物图标。准入、未知材料和缺图的校验入口见[创想卡配方读取](../src/extraction/source/catalog/crafting/read.ts)及[目录校验](../../../packages/schema/src/catalog/validate.ts)。

## 花卉杂交

首批配方按用户提供的四张社区攻略图转录。客户端提供正式花朵身份、系列归属与[客户端获取提示](#客户端获取提示)；亲本到产物的关系来自攻略，成功率和攻略原适用版本未知。该版本已有矮牵牛杂交花色，首批攻略未给出亲本组合。[人工维护 JSON](../data/external/flower-hybridization.json)

## 客户端获取提示

客户端为展示条目配置获取文案和导航动作，用于调查可能的获取途径；它不证明购买、制作或掉落关系，这些仍需对应玩法的证据。

调查使用活动配置 `Persistent/Temp/5662883/GenerateAssets/ed.obb`，并核对 `Persistent/AssetBundle/blocks/00/00000002.blk` 中的 Lua 字节码。显示表 `325` 的字段 `2` 保存一组 `sourceId`，各 ID 引用表 `618` 字段 `0` 的提示行。

| `618` 字段 | 含义与证据                                                                                                                  |
| ---------- | --------------------------------------------------------------------------------------------------------------------------- |
| `0`        | 获取提示行 ID                                                                                                               |
| `1`        | TextMap 文案键                                                                                                              |
| `2`        | 动作说明字符串，样本有「不跳转」「场景追踪」「UI跳转」，也有缺省行                                                          |
| `3`        | 动作码，已确认 `2` 为场景追踪，`1` 为 UI 跳转                                                                               |
| `4`        | `systemjump`；`SourceItemJump.lua` 第 71 行传给 `open_lua_ui`，界面枚举见 `OpenLuaUI.lua` 第 669–691 行                     |
| `5`        | `openstatecfgid`；`FeatureDialog.lua` 第 105–110 行通过 `GetConditionIsUnlock` 查询表 `513`，决定备忘录功能引导入口的可见性 |

来源 `156`「创想卡」的字段 `4`、`5` 分别为 `9`、`8`。来源 `100` 同样跳往界面 `9`，字段 `5` 缺省，文案键在该版本的 TextMap 未命中。表 `618` 解释如何提示玩家、往哪里导航以及何时显示功能入口；商品售价、掉落及奖励条件仍需在对应玩法中查证。

从封存的 `client-read-records.json` 查看 `diagnostics.investigation.acquisitionHints`：用目标展示行的 `id` 找 `displayRows`，再用其中的 `sourceIds` 查 `hintRows.sourceId`。例如树胶 `30031` 的展示行引用提示 `146`。记录保留原行次序、偏移和缺省字段，可复查未收录条目及无法解析的引用。统计覆盖时按 `sourceId` 与展示行 `id` 去重，并区分正式收录与范围外条目。[读取实现](../src/extraction/source/catalog/acquisition-hints.ts)

### 后续玩法调查

调查获取途径时，先用提示选取代表样本和反例，再从具体店铺、配方、行为或奖励事件追到目标物品 ID。正式关系需同时具备可定位的玩法实体或触发条件、可复核的原始记录和目标物品 ID；价格、概率、数量等细节分别核实。已有制作、烹饪、杂交和生长关系可用于对照。该版本正式目录中有 11 件家具和 8 张创想卡带「花卉杂交」提示；缤纷百合箱 `2566` 和它的创想卡 `112566` 都有该提示，制作配方把创想卡连到家具，杂交配方描述的是有亲本证据的花卉关系。

1. **商店。** 格连商店来源 `102` 的 905 件物品中，774 件命中商品物品字段 `659.2`；`665.6` 的 75 个页面候选中，74 个能匹配 `659.1` 的商品组。先确认具体店铺、页面和商品的关系，再查售价、币种、库存和刷新。友邻服饰已有独立的价格 `659.10` 和币种 `659.11` 证据。
2. **树木掉落。** `708.5` 引用 `563` 的砍伐掉落组；银杏树 `50134` 的组 `40001` 包含树胶 `30031`，树胶的获取提示是「旅行惊喜箱」。资料已给出掉落物和来源类型，实际概率与数量还需确认抽取模式、次数及权重的运行时含义。
3. **星屿探索奖励。** 来源 `162` 的 52 件物品中，51 件命中通用掉落表 `563`，而 `655` 指向的 95 个星屿物资组均未命中。下一步从具体星屿的事件、宝箱或探索结算追到奖励池。
4. **任务、活动与友邻事件。** 从具体任务、事件或兑换条件追到奖励，并核对行定位和物品 ID。

## 已确认与未确认

- **友邻服饰占位图（已确认）。** 显示表 `325` 中部分友邻服饰的大小图都指向 `UISprite/Load/Item/Cloud`；解包确认该资源是通用云朵图，同一客户端仍可定位这些服饰的模型资源。资料集将占位云朵视为缺图，保留服饰及原始图片配置依据。[友邻服饰图标](../src/extraction/source/neighbors/outfit-image.ts)
- **生物尺寸换算（基线核对）。** 游戏内显示交叉核对：薄荷炫彩灯鱼 1.5–2.5 厘、酢漿灰蝶 4.6–7.6 厘、红石蟹 5.2–9.2 厘、椰子螺 14–28 厘。核对结果支持端点乘浮点系数，排除另一恒为 100 的字段参与换算；这些是既有基线，不能替代新版本验证。字段读取见[生物属性](../src/extraction/source/catalog/records/creatures.ts)，数值样例见[内容测试](../src/extraction/source/catalog/content.test.ts)。
- **植物成熟天数（未确认）。** 阶段数与候选参数不代表实际天数，应保留生长链和调查值，待游戏内观测或明确运行时语义后再发布。栀子花丛、杜鹃花丛等在关联正式植物后仍有配置阶段，不能在首次命中正式植物时截断链。入口为[生长解析](../src/extraction/source/catalog/plants/growth.ts)。
- **集合主题图（未确认）。** 生物、植物和菜肴主题集合引用了家具图标，作为系列展示图的用途尚未确认，因此不以成员图片或拼图替代。后续需确认客户端实际展示用途，而不只是确认资源存在。[图片筛选](../src/extraction/source/catalog/records/common.ts)
- **生物时间与栖息地（未确认）。** 候选表不能仅凭相同编号关联；部分旧标签文本键已经失效，应沿当前显示键与标签语义调查。入口为[目录词汇关联](../src/extraction/source/catalog/vocabulary.ts)。

客户端读取记录保留排除项、候选值及未确认原因，字段依据报告说明最终字段的来源。新增判断时记录来源和适用版本，无法找到原始依据时标为待确认。

## 小栖地

调查使用客户端活动配置 `ed.obb`；玩法表 `288` 和显示表 `291` 按模板 ID 对齐。收录依据来自游戏内 Lv.5 时的观察、任务和对白，逐条判断记录在[准入清单](../src/extraction/source/vignettes/admissions.json)。游戏内观察保留的是调查结论。

- **数量来源。** `HabitatInfoPage.lua` 第 490–495 行从 `ReferEntities` 的 `RepairItem.Count` 构建显示条目，`HabitatInfoItem.lua` 第 87 行在数量前加 `x`。42 个可比模板中只有观星露营地的座椅数量不同：玩法表 `288.10` 为 3，显示表 `291.7` 为 2，同一模板另列灿烂星双人椅 1 张。网站布景要求采用客户端显示数量；玩法计数如何纳入指定物品及实际完成判定仍待验证。[表字段来源](../src/extraction/source/vignettes/profile.ts)
- **家具尺寸。** `HabitatInfoItem.lua` 第 177–195 行显示 `GridWidth` 和 `GridHeight` 分别除以 2 的结果。户外餐厅地、悠然野餐地的桌子和座椅显示 `1 × 1`，瓶花闲坐地的桌子显示 `2 × 2`；这五条要求的客户端示例家具均带对应尺寸标签，包括映央小圆桌（1516）和映央大圆桌（1515）。网站据此用相同宽高顺序的家具尺寸标签筛选候选；实际匹配算法及是否接受旋转仍待验证。[家具标签尺寸读取](../src/extraction/source/catalog/records/furniture.ts)
- **承载条件。** 户外餐厅地（1006）的玩法表 `288.10` 记录桌子 `1,置物桌,2,2*2`（「置物桌」标签、数量 2、尺寸 2×2）和食物 `2,置物桌,食物,2`（承载于「置物桌」、数量 2），显示表 `291.7` 为这两条各自附上示例。食物条目除承载条件引用「置物桌」外，没有尺寸、桌子物品 ID 或要求行引用，玩法表 `288.11` 也没有为该布景配置物件关系。晴日特调地的饮品承载条件直接引用美食展台（1852）。网站在摆放规则中描述承载条件，网站图鉴仍可按承载条件反查。[布景要求读取](../src/extraction/source/vignettes/conditions.ts)
- **进度与完成。** `HabitatTrackingItem.lua` 第 126 行调用 C# 接口 `CsHabitatModuleUtil.GetHabitatTotalProgress` 读取进度，`BlueprintHabitatData.lua` 第 54 行调用 `IsHabitatRestored` 读取完成状态；两个脚本只读取结果。食物是否必须放在计入尺寸要求的两张桌子上，仍需确认完成判定的实现或通过游戏内摆放验证。

排序 `32–34` 的三条模板共享发现线索 `6212`，触发条件及开放时点待确认；姹紫嫣红地排在 `99`，同样留作待证；名称带 `(test)` 的条目只留在客户端读取记录中。客户端帮助文案 `443862490` 将备忘事项和装饰能力列为发现途径，玩家当下的可见性取决于游戏进度。

生态参数及布景预览路径留在客户端读取记录中；生物出现时机、概率与逐件坐标仍待确认。

## 星海与星屿

调查使用活动配置 `Persistent/Temp/5662883/GenerateAssets/ed.obb`；以下根表和字段编号来自该文件，文案取自同一文件的 TextMap。客户端使用「星海」「星屿」和「星海地图」等称呼，版本配置见 [profile](../src/profile.ts)。

星海资料收录区域探索列表与邂逅池里能确认归属的星屿。范围外的星屿定义与未确认的多区域候选保存在客户端读取记录中。详情页的展示物资可关联仅供引用物品，正式收录仍遵循物品目录的准入依据。

- **区域与星屿。** 根表 `652` 的区域为「禾夏H83区」「沐雪季·禾夏H84区」「塔法T31区」。每区的星屿向量（字段 `6`）与根表 `651` 按星系和层号分组的有序列表完全一致，可用星屿 ID 关联根表 `654`；这些列表只覆盖星屿定义的一部分，其余星屿的区域和实际航路生成规则仍待确认。H84 区的解锁提示指向禾夏 H83 区的对应星门。
- **物资。** 星屿详情的 `IslandDetailsPanel.lua` 读取 `displaybiologyicon` 和 `displayspecialtyicon` 展示「生物」及「特产」，分别对应根表 `654` 的字段 `25` 和 `26`，可用物品 ID 关联根表 `318`；空字段表示对应展示栏目缺少配置。根表 `655` 的资源映射还可关联根表 `563` 的掉落组，覆盖矿石、昼夜生物和季节植物；掉落组如何分配到具体星屿、数量和概率如何计算仍待确认。
- **友邻。** `StarExploreTeleportationDetail.lua` 读取 `BStellarSeaNpcPoolCfg` 的 `layerlist` 和 `npcid`，填充区域的邂逅友邻列表。根表 `653` 的友邻 ID 对应根表 `41`，区域向量对应根表 `652`，同一行的星屿向量对应根表 `654` 中的 NPC 岛；多位友邻可以引用同一星屿。季遇文案说明当季友邻会随季遇结束远行，实际出场还需按游戏内状态核对。
- **图像与坐标。** 区域配置引用地图 SDF 和站点图，星屿配置可关联插画和雷达图标。地图预览图可从资源索引找到，但预览图与区域的绑定仍待确认，因此保留为观察候选。`StarExploreTeleportationPage.lua` 从运行时列表读取星屿、星门与站点的 `Position.x/z` 并绘制图标；界面坐标换算已验证，完整坐标列表和上游来源待确认。
