# 业务确认与调查

> **维护范围** 仅当准入策略或业务解释发生变化、关键证据足以确认或推翻已有判断，或待确认问题影响某项具体收录决定时，才更新本文。准入策略变更写入下方总表的对应行，证据变化时优先修订正文已有条目。沿用既有规则即可判断的普通样例无需逐项登记。

除另有注明，证据来自客户端 `0.95.2`、数据修订 `1449213`，换版须复核。客户端配置、客户端试算和游戏实际行为是不同的证据；未实测不作运行时结论。复核入口见[客户端资源提取](../README.md#输入缓存与产物)。

## 各子项准入策略

| 子项                                                     | 准入条件                                                                                                                                                            |
| -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 正式物品（通用）                                         | 从客户端内容表收录能核对身份和分类的非外观条目。表外物品须满足下列专项条件，或由[补充收录清单](../src/extraction/source/catalog/supplemental-admissions.json)确认。 |
| 家具、普通穿搭、[生物](#生物)、[植物](#植物)、菜肴和材料 | 沿用正式物品通用条件。种子、作物株和花株见下列专项条件。                                                                                                            |
| [集合](#物品与集合)                                      | 内容表有可识别为套组、套装或系列的条目。成员须是同类正式物品，且有明确的客户端归属关系。                                                                            |
| 仅供引用物品                                             | 范围外物品的身份可核对，且有配方、掉落、支付货币等明确关系需要引用时，保留其身份供关联使用。                                                                        |
| [购买报价](#购买报价)                                    | 须能确认直接交付物、支付货币和单次购买的金额规则。格连、络米电视购、友邻衣橱和星空街市还须从非测试店页追到商品组，万礼馆以专属礼品表为准。解锁卡的报价归卡片。      |
| [发型、眼睛、眉毛和肤色](#外观与染发)                    | 有已确认的初始选项、络米电视购商品或卡池获取配置。                                                                                                                  |
| [面部饰品](#外观与染发)                                  | 当前仅补录已确认礼包中的嘭嘭杏鲍菇雀斑。普通可穿戴面饰沿用穿搭条件。                                                                                                |
| [染发可选色组](#外观与染发)                              | 正式发型的可选色组须有解锁配置。区域默认色块可独立保留。                                                                                                            |
| 创想卡                                                   | 客户端物品类型为创想卡，有与卡片同 ID 的制作配方，且产物为正式家具。                                                                                                |
| [种子](#植物)                                            | 有确定性的生长配置，且能沿配置关联到正式植物。                                                                                                                      |
| [作物株](#植物)                                          | 已收录作物的成熟阶段与收获配置指向同一作物。幼苗、枯萎株、杂草及环境植物沿用原有身份。                                                                              |
| [花株](#植物)                                            | 花株表中的收获物指向正式花朵。种子生长链以外的花株也按此条件收录。                                                                                                  |
| [花卉杂交配方](#花卉杂交)                                | 绑定目标版本的[人工维护配方](../data/external/flower-hybridization.json)明确列出该组合，且亲本和产物均为同一正式花卉系列的成员。                                    |
| 友邻                                                     | 客户端 ID 在[友邻准入名单](../src/extraction/source/neighbors/allowlist.ts)中。                                                                                     |
| [友邻服饰](#友邻与服饰)                                  | 有明确的玩家服饰对应关系，或为名单内友邻的专属服饰。明确归属名单外友邻的服饰排除。                                                                                  |
| [小栖地](#小栖地)                                        | 由装饰能力等级或任务直接解锁，或沿前置小栖地逐级回溯到这样的模板。模板自身和沿途任一前置的名称带 `(test)` 时排除。                                                  |
| [星海区域](#星海与星屿)                                  | 客户端有区域配置，能核对所属星系、层级及该层的探索列表。                                                                                                            |
| [星屿](#星海与星屿)                                      | 区域探索列表或区域邂逅池明确引用该星屿，且该星屿不属于测试定义。其余定义只保留在客户端读取记录中。                                                                  |

## 植物

- 栀子花丛、杜鹃花丛等在生长链关联到正式植物后仍有后续阶段，应保留完整链。**成熟天数待确认**：阶段数和候选参数不能直接作天数，需游戏内观测或明确的运行时语义。
- `ed.obb` 表 `144` 的成熟阶段与产物（字段 8、10）可与表 `137` 的收获物（字段 1）交叉核对。`137:10308` 缺少已收录作物的成熟阶段依据。
- 表 `241`（字段 1、2）中，灿黄百合株 `56000` 指向灿黄百合 `56200`，即使已收录种子的生长链未包含该花株，也能确认其收获物。该表中的 `50129` 未指向正式花朵。

## 友邻与服饰

- **房屋升级**按友邻准入名单从表 `310` 定位房屋。目标阶段表 `315` 的字段 `11` 指向共建箱建材组，字段 `26` 指向订单图纸组。表 `377` 按组列出物品与数量，表 `318` 提供身份；任务文案（文本键 `472913529`、`2215723864`）分别说明领单与投料。12 位友邻的特色小屋均配置一张图纸，初始草顶小棚均未配置升级要求。房屋可共用物品组，多杰朗与万象馆共用图纸组 `10010`，收录范围按房屋归属判断。
- **社交头像与室内图**在客户端 `0.95.2` 修订 `1449213` 各有 12 张。社交头像按资源名的友邻 ID 归属，表 `547` 字段 `2` 额外引用其中 10 张，行 ID 属于头像配置。室内图有 11 张由表 `420` 的友邻 ID 与路径确认；幻雪的室内图、幻雪和纳蕾娜的社交头像仅有资源命名证据。
- **订单图纸图标**按升级关系中的图纸物品 ID 读取表 `325` 字段 `4`（小图）和 `5`（大图）。幻雪和纳蕾娜的两件图纸共用一套图标，蛮蛮的两个槽位均配置大图。

## 小栖地

- **发现条件：** 发现条件表和装饰能力等级表都支持 Lv.6；专注伏案地、裁荷清幽地和野风纳凉地据此准入，但尚未实测开放。截图只证明特定账号的发现状态，排序不证明准入；姹紫嫣红地仍无已确认的发现途径。
- **数量冲突：** 观星露营地（`1007`）的座椅在玩法表为 3、显示表为 2。两值分别保留，网站采用显示值，不能据此断定实际完成只需两把。[座椅差异回归样例](../src/extraction/source/vignettes/conditions.test.ts)
- **承载条件：** 户外餐厅地的食物只引用「置物桌」标签，没有桌尺寸、桌 ID 或要求行引用；晴日特调地饮品直接引用美食展台。食物是否必须放到计入尺寸要求的桌上、旋转是否影响匹配，仍需游戏内验证。
- **待确认：** 生态参数和预览资源保留在读取记录中，但生物出现时机、概率与预览逐件坐标不能从当前证据推出。
