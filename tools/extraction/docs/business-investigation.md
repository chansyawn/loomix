# 业务确认与调查

> **文档规则：** 各业务主题只记录 **准入规则**、**关键确认** 和 **待确认**。**准入规则** 说明收录范围；**关键确认** 只列非直觉、会影响提取判断的结论；**待确认** 记录未决问题和下一步。名称、图标、常规套组归属等直觉信息不逐项列举。
>
> **说明：本文不是最终结论。** 所有条目都是基于当前客户端版本和现有证据的工作结论，可能不完整或有误；新证据、游戏内验证或版本更新后应重新核对，不能把本文当作不可推翻的“真理”。引用前应回到客户端读取记录、字段依据和实际验证。

本文维护具体业务的收录依据、已确认结论与待调查事项。除特别注明外，结论基于客户端 `0.95.2`、数据修订 `1449213`，不能自动推广到新版本。跨业务解释原则见[提取要求与规范](extraction-requirements.md)，客户端换版与调查见[提取维护](extraction-maintenance.md)（待补充），概念见[领域术语表](../../../GLOSSARY.md)。字段映射、算法与数量以代码为准。

## 物品价格与交易

**准入规则**

- 客户端 `0.95.2`、数据修订 `1449213` 中，格连、络米电视购、友邻衣橱和星空街市的商品须沿非测试店页关联到商品组。万礼馆使用专属礼品表。直接交付物、支付货币和一次购买的金额规则均可核对时才收录。解锁卡的价格归卡片，货币按物品 ID 区分；物品表 `318` 有四种名为「碎钱」的物品，格连的支付货币为 `200002`。
- 发布资料保存商品级购买报价，字段依据记录其配置行或说明文案。入口、上架条件、缺页和未能准入的商品保留在客户端读取记录。游戏中的实际开放状态另行核实。普通回收、寄售、菜市与地区充值价继续按各自交易规则调查。
- 同店、同交付物、同币种出现异价时，能核实来自任务或限时货架的报价统一标注「任务/限时货架」。限时依据是该条商品在店内的所有入口都配置了相同的起止时间，新商品符合时自动标注。任务依据按修订核对具体商品行、追踪条件和任务文案。任务文案只提到购买用途时，不能据此限定金额。同价商品只要有一条未注，合并展示时就只列金额。衣橱教程的等额补足说明按店展示。
- 仅供引用物品中，实际用于报价支付的货币优先采用物品显示表的小图，无法定位时再查大图。图标沿用物品 ID 和网站图片索引。

**关键确认**

- 客户端 `ed.obb` 的通用商品表 `659` 有 2,843 条记录，涉及 1,150 个物品 ID。货币常由店铺确定。格连的购买说明明确使用碎钱（文本键 `2798898123`），小麦种子的商品金额为 2。络米电视购的「络米购物」页指定足迹（表 `712–714`）。同名的眠月睡袍有两种物品身份。电视购的商品 `302`、`515` 都交付玩家款，分别为 1,500 和 1,800 足迹。友邻衣橱款为 600 友邻服饰币，衣橱教程说明服饰币不足时可用等额碎钱补足（文本键 `88034602`）。
- 表 `663` 按商品 ID 配置每日购买次数对应的价格。星锚商品 `2` 的常规金额为 300 足迹，次数 `0/1/2` 各配置 `100/200/200`。星空街市的礼帽魔术券也有阶梯，次数 `0` 的金额明确为 `0`，游戏帮助说明兑换使用街乐果冻（文本键 `974612840`）。缺少金额的商品与明确配置零价的档位应分别处理。
- 格连的同物异价见于每日刷新页、任务关联的固定页和限时刷新页（表 `659`、`665`）。简约饮水器的 290 碎钱在页 `25–27`，360 碎钱在页 `71`。页 `70–71` 的配置时间为 2026-08-27 12:00 至 2026-09-03 12:00。粉白陶瓷杯在限时页 `70` 和任务固定页都有 150 碎钱的报价。格连购买弹窗将商品列表中的单价乘以折扣百分比后向上取整，见 `GlennShopPanel.lua:245`（对象 `ec91e089`）。
- 客户端任务文案点名向格连购买花叶拼布沙发椅、粉白陶瓷杯、温暖日光灯，分别为哈佩诺、绵朵莉和缇卡准备家具（文本键 `2825703257`、`216535044`、`715774891`）。固定页 `49–51` 的三件报价逐项关联到对应任务的追踪器（对象 `4f3420ed`）。沙发椅还在页 `55–57` 以 460 碎钱关联「绵朵莉与玩偶灵感」及小栖地「玩偶灵感取材地」。因此同一金额也可能有不同适用条件。
- 玩家款眠月睡袍的两条电视购商品都在「每日上新」。1,500 足迹那条的追踪器 `3509`、`3510` 对应「篝火派对的邀请」「欢乐的派对时光」。「篝火派对的服饰」任务 `4322` 明确要求在电视购买袍并给自己换装（文本键 `2452989747`）。1,800 足迹那条没有这两个行条件。`TVShopData.lua:60` 从返回的 `PageList` 读实际页面，页中有 `GoodList`（同文件第 838 行，对象 `b3a5aba1`）。「每日上新」还允许将商品加入心愿购保留（文本键 `3012755044`）。
- 电视购的多件合计有客户端算法可查。`TVShopData.lua:648` 用运行时单价及已售数核对次数档；匹配后计算多件总价时，未列次数沿用最高次数档的金额，无法匹配时按运行时单价乘件数（同文件第 731 行）。例如星锚的最高次数档为 200 足迹。这个算法解释购买弹窗的试算；库存、限购和服务端扣款仍需单独核实。
- `CommonCoinItemView.lua:182` 用货币 ID 加载物品图标（对象 `a263af52`）。报价所用的五种货币均可按支付物品 ID，从表 `318` 取得中英文名称，从表 `325` 取得两处图标引用。五种都已从资源包实际导出。足迹的小图和街乐果冻须在配置目录内按唯一的 Sprite 名定位。万象礼券、街乐果冻各自的两处引用指向同一个对象。
- 扩展货币资料时，背包枚举、货币标签、具体支付用途需要分别核对。`BackBagCommon.lua:12` 的 `coin_type`（对象 `88ca166d`）含 14 个不同的非零 ID，露芽有两个别名。对照物品表和图标索引，其中 12 个有名称及可定位图标，卡灵结晶缺图，`luca` 的 `30201` 在表 `318`、`325` 均缺行。另有星果 `200019` 在枚举外有物品资料和充值配置。只按「货币」标签筛选则会漏掉足迹、友邻服饰币，也会命中另外三种同名碎钱。用途文案可独立确认奇迹足迹兑换友邻印象礼、奇迹星铃兑换毕业礼、赞赞果冻兑换街市奖励（文本键 `1039421574`、`2487248739`、`3879940223`）。这些用途关联到具体商品仍需逐条核实。
- 衣橱有入口的 182 条商品覆盖 91 件服饰，金额与旧口径逐件一致。旧口径另含组 `503` 的冬日雪宴裙、发饰、鞋，三件保留为有价但入口待确认的候选。电视购配置引用了缺失的页 `18`、`20`。街市组 `82` 有页面关联，其三测开放情况仍待实测。
- 万礼馆表 `672` 中有六条礼品的首字段同为 `9`，结合交付物 ID 可区分各行。表 `663` 的次数价只关联通用商品表 `659`。万礼馆首字段 `2` 的知秋杏花毯为固定 35 万象礼券。
- 万礼馆单独配置礼品、金额和货币（表 `672`），例如甜蜜之家挂饰需 25 万象礼券。寄售架则由卖家设定价格和数量（文本键 `1380489113`）；阿莱的梗力收购会按收购品和舞台发言表现调整报价（文本键 `974728160`）。
- 今日菜市按市场收购作物。教程说明同一市场共享价格，昨日产量较低的作物今日倾向于涨价，非当期收获的作物另有折价（文本键 `3495403078`、`2883679833`）。表 `152` 的调价时间配置和表 `711` 的菜市教程均指向每日 `12:00`、`20:00`；另一份帮助（文本键 `353026141`）称 `04:00` 调价、中午和晚间只更新种植量。前者有两处依据，实际生效时间仍需看游戏内菜价板。
- 格连的普通出售页按背包里的**物品实例**取价。`BackBagData.lua:366` 对每个选中的实例计算 `CsPacketModuleUtil.GetItemPrice(item_guid) × 数量`；`SellPacketPage.lua:283` 汇总各堆叠小计，取总额的整数部分展示。确认时，同页第 177 行把实例 GUID、数量和 NPC ID 交给 `PlaySellReq`。该页收到 `OnPlaySellRsp` 后只标记出售成功。复核来源为快照 `Persistent/AssetBundle/blocks/00/00000002.blk` 内的 Lua 对象 `c567a48c`、`1cbbb641`。
- `CSDefine.lua:914`（对象 `b72e7d7a`）将上述工具绑定到 `miHoYo.HYG.LuaBridge.CsPacketModuleUtil`。同包还有携带物品数据的调用：`ItemMain.lua:827` 传 `(item.GUID, item)`，`ItemNumDialog.lua:237` 的出售分支传 `(0, data.item_data)`（对象 `359d8fce`、`64a046e9`）。因此，追查原生方法时需能解释这两种传参方式以及普通出售页只传 GUID 的方式。
- `GameAssembly.dll` 可以直接核对配置类型和表号。`BItemCfg`、`BItemCfgTable` 的类型记录由具名封送信息识别，两处原生代码分别引用这两个类型，并在 RVA `0x7b78f6a`、`0x7b7907a` 以偏移 `0x28e` 查根表，对应从零计数的字段 `325`（`4 + 2 × 325`）。用同一方法可将 `BCropPriceRangeCfg` 对到表 `148`（RVA `0x7b6174a`，偏移 `0x12c`）。
- 菜市有两个具名价格。`GeLianFoodMarketPriceItem.lua:107` 将 `BItemCfg.price` 显示为原价，下一行用报价的 `FinalPrice` 显示新价。`GeLianMarketSellAdapter.lua:42` 也直接用 `BItemCfg.price` 计算折价，结合市场倍率，并在有上下限配置时按 `BCropPriceRangeCfg.pricemin/pricemax` 限价。同包对象分别为 `b3cf59e8`、`f56a4688`。衣橱回收则按服饰配置 ID 调用 `CsShopModuleUtil.GetNpcClothRecyclePrice`（`NpcClothGelianSellPage.lua:261`，对象 `df8c9b0c`）。

**待确认**

- 已能将异价商品关联到具体任务，但表 `659` 两组追踪条件各自在何时使商品可见、可买或下架，仍缺同一账号推进任务前后的货架对照。可优先记录篝火任务前后两个眠月睡袍商品 ID 的出现情况及确认价；格连可对照任务固定页和当日刷新页，核实两价能否同时购买。
- `BItemCfg.price` 的首要候选是表 `325` 字段 `14`。按物品 ID 对照表 `148` 的 65 个作物，字段 `14` 全部有值，字段 `13` 全部缺省。56 个作物的字段 `14` 恰等于菜市下限的两倍、上限的一半。梦幻果王小麦、水稻、辣椒是明显例外，字段 `14` 均为 100，菜市范围均为 200–800。
- 原生访问器 RVA `0x78debc0` 按行内偏移 `0x20` 读取字段 `14`，缺省返回 `0`。尚缺两段证据：该访问器的属性名，以及普通回收 `GetItemPrice` 对该字段的读取。也未确认实例星级等因素是否改变返回值。
- 游戏内可用两件服饰区分几种取价方式。全表字段 `13`、`14` 同时有值的 1,409 行中，1,408 行为 5∶1，雅克想象帽为 200 与 20。粉眠恐龙睡衣两字段为 17,500 与 3,500，格连商品买价为 17,000。可分别记录单件普通出售的预览金额与碎钱到账差额，再用同种不同星级的生物核对实例差异。
- 付费商品可定位到礼包与充值档位，如种星月卡 `monthcardtier1800` 和「60枚星果」`coin60tier600`（表 `153`、`157`）。客户端的「1 元 = 10 星果」明确用于连接测试的充值返还（文本键 `3918012022`）。各地区实际售价仍需带地区和币种的支付页核实。

## 外观与染发

**准入规则**

- 发型、眼睛、眉毛和肤色需有三测初始选项、络米电视购或已确认卡池的获取配置。面部饰品收录已确认礼包中的嘭嘭杏鲍菇雀斑。普通可穿戴面饰归入穿搭。
- 染发配置限正式发型。可选色组须有解锁配置，区域名称取游戏显示文案。区域的默认色块单独保留。

**关键确认**

- 络米电视购的发型和眼睛商品通过解锁卡关联外观，有些商品解锁的外观未被写入客户端内容表。玩家截图用于核对发型正例。内容表、获取提示和备用解锁表可用于追查差异。
- 灰色盘和专属默认色组缺少解锁配置，留在读取诊断中。默认色块仍可用于对应发型，白色盘仍可引用共享色块。

**待确认**

- 商品组 `82` 混有直接商品与外观解锁卡。表 `46`、`47` 将其关联到星空街市「街市风尚／服装」页，已解析的络米电视购页面中没有该组。三测期间这些外观是否实际开放仍待核实。

## 植物

**准入规则**

- 种子需有可关联正式植物的确定性生长配置（作物、固定幼苗或树木种植）；随机种植种子和不关联正式植物的种子不纳入。
- 作物株须由已收录作物的成熟阶段与收获配置相互印证。花株按整张花株表中指向正式花朵的配置收录。幼苗、枯萎株、杂草及环境植物沿用原有身份。小栖地通过植株自身的物品 ID 或玩法标签匹配布景条件。
- 花卉杂交配方只收[人工维护 JSON](../data/external/flower-hybridization.json)中列出的亲本组合；配方必须绑定目标客户端版本，并引用正式花朵系列中的正式花朵，未列出的组合不推断。

**关键确认**

- 该版本已有矮牵牛杂交花色，但首批攻略未给出亲本组合。
- 客户端 `0.95.2` 的 `ed.obb` 中，表 `144` 的成熟阶段与产物（字段 8、10）和表 `137` 的收获物（字段 1）对应出 85 个作物株。`137:10308` 未命中已收录作物的成熟阶段。表 `241` 的字段 1、2 对应出 93 个花株，其中 42 个在已收录种子的生长链中，另外 51 个包括灿黄百合株 `56000`，可收获灿黄百合 `56200`。`241` 中的 `50129`、`50146`、`50148` 均未指向正式花朵。

**待确认**

- 植物成熟天数：阶段数和候选参数不代表实际天数，需游戏内观测或明确运行时语义；栀子花丛、杜鹃花丛等在关联正式植物后仍有配置阶段，不能截断生长链。
- 花卉杂交成功率与攻略原适用版本未知；补充矮牵牛等已有花色的亲本组合。

## 小栖地
