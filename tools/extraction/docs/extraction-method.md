## 解释与证据原则

名称、图标、配方引用或相同编号本身不能证明正式收录资格；人工收录也不授权补造描述、属性或关联。范围外引用不扩大正式收录范围，其表示方式遵循共享契约。具体准入依据和未确认事项见[业务确认与调查](business-investigation.md)。

创想卡首批以正式家具为产物范围，要求客户端物品类型与同 ID 配方共同确认身份。正面沿用客户端指定底图，由网站叠放产物图标。准入、未知材料和缺图的校验入口见[创想卡配方读取](../src/extraction/source/catalog/crafting/read.ts)及[目录校验](../../../packages/schema/src/catalog/validate.ts)。

未知、已确认缺失与解析失败需要分别表达：缺少证据不能变成默认值，已匹配配置但无法解析或导出的情况不能伪装成缺失。

解释客户端数据时，优先使用明确关联及当前显示配置，不通过名称相似度或“碰巧可读”推断关系和类型。显示配置可能有重复 ID，应比较所需字段的语义值；相对引用地址不同不代表值不同，范围内语义冲突则必须停止，避免读取顺序决定结果。

## 流水线的设计取舍

**源读取、领域组装与交付分别负责不同问题。** reader 在读取客户端时同时记录值、具体依据和图片用途，避免事后猜测来源；组装只消费观察与原图，不回读客户端补值；交付消费已验证的封存结果。这样可以分别调查来源解释、领域关系和资源转换，减少修改一处时必须理解的范围。

**封存输入和候选，支持复核决策。** 不只保存最终数据与选中的图片，还保存冻结来源和参与选图的候选。否则只能证明最终文件未损坏，无法重新判断选图是否正确。源对象身份与 PNG 内容身份分开，避免相同像素掩盖不同来源。交付图片规格由用途决定，参数只在转换实现中维护。

**恢复缓存不是事实来源。** 只为昂贵解码和外部原图导出保留恢复缓存，复用前重新验证；完整封存结果可脱离这些缓存验收。输入、工具或实现发生变化时通过内容身份区分结果，避免把旧缓存当成新版本的成功证明。缓存结构与封存协议不在文档中另行定义。

**可重现性与正确性分别验收。** 从同一观察重新组装得到相同字节，只能说明可重现，不能排除 reader 一直读错。独立来源验收直接对照冻结输入，不调用生产分类、关联或选图 reader 生成期望；涉及来源解释的变更应检查“数据与证据一起被改错”仍能被拒绝。离线提取验收与核对实际客户端的整链验收也不能相互替代。

## 客户端更新与调查

先确定当前配置及资源清单，再调查解码布局与领域解释。客户端可能同时保留基础配置、更新配置和临时下载配置；历史调查中忽略 Temp 会选到旧配置，因此不能仅凭目录名称或文件存在选择输入。未安装的可选资源同样不能作为内容不存在的证明。

更新时重点检查：字段宽度及引用类型、TextMap 包装、标签与显示对象位置、缺省值含义、准入与成员关系、图片用途。解码边界和回归样例见[解码测试](../src/extraction/source/decode/decoding.test.ts)；具体版本、字段及数量在 profile 和各领域实现中维护，不在本文复制。旧数量只用于辅助发现差异，不应通过删除新增记录或直接修改期望数量让验收通过。

调查完成后更新相应实现、版本绑定清单与有意义的非 UI 回归测试，再运行：

```sh
vp check
vp run @loomix/extraction#test
```

真实客户端适配还需按操作指南完成提取与整链验收，检查新增、排除和未确认项的依据；单元测试通过不代表新版本数据已确认。输出契约变化时按共享契约的版本规则协调消费方。

仅在使用方式、决策依据或适用边界变化时更新文档；普通字段、参数与产物结构变更由代码及测试承担。局部算法陷阱就近说明，跨模块决策保留在本文，不新增重复规格。
