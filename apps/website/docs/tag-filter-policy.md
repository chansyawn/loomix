# 标签筛选策略

本文维护「全部」页与食材筛选的用户可观察策略及适用边界。配置名单、URL 参数和名称解析算法以代码为准；仅在策略含义或适用范围变化时更新本文。

## 全部页

[全部页策略](../src/features/catalog/tag-filter-policy.ts)用内部名称选择根标签，避免配置依赖可能随快照变化的标签 ID。可见树只保留至少一条正式物品直接引用的标签及其祖先；没有可见标签的根隐藏，集合记录不参与判断，与页面的数据范围一致。

友邻详情展示完整的偏好标签。可在「全部」页筛选的标签链接到对应结果，其余标签只显示名称。仅被友邻喜好引用的标签不会因此进入筛选树。

## 物品详情

概览优先展示有辨识度的标签，例如菜肴的食品分类和原料特征、家具类型、服饰款式和生物细分类。同一分类分支优先展示物品直接引用的最具体标签。星系风味和植物产区直接链接到对应的「全部」页筛选。家具的占地尺寸与直接引用的尺寸标签一致时也提供链接。

通用信息末尾的「筛选标签」字段按物品的引用顺序平铺所有在「全部」页可筛选的直接标签，包括已在其他字段展示的值。每个标签都链接到对应的单标签筛选结果。只有物品直接引用的父标签才会列出。集合不继承成员标签。没有可筛选标签时隐藏该字段。

「食材标签」链接到食材浏览页。同一标签出现在「筛选标签」中时，链接到「全部」页。

## 食材筛选

食材浏览页与烹饪页的「所需食材」共用[食材分组策略](../src/features/ingredients/tag-filter-policy.ts)，按分类、颜色和食材品质筛选：

- 组内满足任一条件，组间同时满足；勾选父级不会连带勾选子级，但匹配包含其子级。
- 没有正式食材引用的标签隐藏；可见标签在当前结果中计数为零时置灰。是否可见与当前结果计数是不同判断。
- 无效、未知或不可见的 URL 标签不形成筛选，避免旧链接留下无法操作的条件。参数与解析入口见[查询状态](../src/features/ingredients/search.ts)和[标签筛选](../src/features/ingredients/tag-filter.ts)。

一级食材标签要求明确归属，防止客户端新增类别时悄悄漏掉筛选维度。新增一级标签时先判断是现有分类、新维度还是需要明确排除；新增深层标签通常沿祖先归组。

当前检查会拒绝未归属的一级标签。若决定暂不展示，应先明确排除原因、作用范围及配置表示，再同步实现与验证；不能只删除分组配置或放宽未归属断言。用途排除也不等同于一级标签已完成归属，具体规则见[食材检查](../scripts/release-checks/checks/tag-filter/ingredients.ts)。

## 中文名清理

两处筛选树与 chip 共用[名称解析](../src/features/omnidex/tags.ts)，用官方名称、显式特例和前缀清理消除内部结构命名。物品详情的筛选标签沿用目标筛选器的名称。占地尺寸保留字段本身的数值格式。

不同分支允许同名，chip 通过完整路径区分；同一父级下的重名会使选项难以辨认，应通过检查发现并明确处理。具体特例与解析顺序只在实现中维护。

## 维护与检查

更新资源或策略后，按[发布契约检查](release-checks.md#运行方式)验证。根标签或类别变化从对应策略文件入手；显示名称问题从共享名称解析入手，避免在各页面分别修补。

完成[贡献指南](../../../CONTRIBUTING.md#提交-pr)要求的检查，并人工打开「全部」页、食材浏览页和烹饪页，确认筛选树、搜索、组间与组内匹配、chip 移除及友邻标签链接行为。普通配置项增删无需在文档复制名单。
